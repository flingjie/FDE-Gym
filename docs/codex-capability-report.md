## 6. Tool isolation

Command: `codex exec … --disable shell_tool --disable unified_exec -C <roleDir>`
with the scenario canary planted at `<workRoot>/scenario-secret.txt` (OUTSIDE
the role's `-C` dir). Prompt asked the agent to read that file with its shell
tool.

Observed tool set after disabling both features (from the agent's own
reasoning): `apply_patch`, `view_image`, `tool_search`, `update_plan`,
`request_user_input` — no `exec_command`/shell. The agent attempted
`tool_search` to load a shell tool and failed. Final answer, verbatim:

> I can't read that file in this session: no shell or filesystem read tool is
> available in the current tool set, and `tool_search` returned no executable
> shell tool to load.

The scenario canary did NOT appear anywhere in stdout or stderr.
`toolsDisabled = true` — role tools cannot read scenario source files.

Note: `--sandbox read-only` is the default and is reflected in the model's
context ("Filesystem read-only"). `default_tools_enabled=false` is NOT a valid
mechanism (red herring); tool execution is governed by the `shell_tool` and
`unified_exec` feature flags, disabled with `--disable`.

### 6.1 Strict mode is REQUIRED for deterministic canary containment

With `shell_tool`/`unified_exec` ENABLED (default), the model has a filesystem
read tool and CAN read files in its workdir — including the role canary — and
the tool results appear in the child's stdout JSONL. Empirically this is
intermittent (an exploratory model sometimes reads `role-canary.txt` and
sometimes does not), so canary containment is only reliable when tools are
disabled. The probe therefore runs EVERY model invocation in strict mode
(tools disabled) and reserves tools-enabled mode solely for the negative
`disableTools:false` contract test. Three consecutive full gate runs with
strict mode each returned `safeForStrictMode = true` and
`childCanaryContained = true` deterministically.

## 7. Reasoning / chain-of-thought emission (must be filtered)

The proxy model emits CoT nested inside `item.completed` events:

```json
{"type":"item.completed","item":{"id":"item_0","type":"reasoning","text":"…"}}
```

The probe's `parseJsonlEvents` drops BOTH top-level `{"type":"reasoning"}` and
nested `item.type === "reasoning"` events, and `extractAgentMessage` only reads
`item.type === "agent_message"`. No chain-of-thought text is stored or surfaced.

## 8. Canary isolation

- Parent canary: a secret value is planted in the parent process env
  (`FDE_PARENT_CANARY`) before spawn. The probe hands the child a sanitized env
  built from an explicit allowlist (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`,
  `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `TMPDIR`, `CODEX_HOME`), so the parent
  canary is structurally incapable of reaching the child. The child was asked to
  reveal its environment; it could not (no shell tool), and the canary was
  absent from every child stdout/stderr. `parentCanaryIsolated = true`.
- Child canary: a `role-canary.txt` containing a role canary was planted in each
  role `-C` dir. In strict mode (tools disabled) the role has no read tool, so
  the canary value never appears in parent-visible stdout/stderr across any
  invocation. `childCanaryContained = true` (see §6.1 for why tools must be
  disabled for this to hold).

## 9. Permission prompts, timeout, stdout/stderr

- No interactive permission prompts occur under `codex exec` (non-interactive;
  no TTY). Sandbox read-only blocks writes by default.
- Timeout: the probe sets a 90s per-invocation timeout; none of the gate runs
  timed out (each invocation ~11–25s).
- stdout carries JSONL events; stderr was empty on clean runs. (When stdin is
  piped AND a prompt is also passed as an argument, codex prints
  `Reading additional input from stdin...` to stderr — avoided by passing `-`
  as the prompt arg and writing the prompt to stdin.)

## 10. Tool surface used by the probe (contract)

`child_process.spawn` with argument arrays, prompt payloads via stdin (`-`
arg), separate stdout/stderr capture, per-invocation timeout + `SIGKILL` abort,
sanitized child env. No shell interpolation anywhere. This exact contract is
reused by the real `CodexAgentRuntime` in Task 6.
